- 2026-11-28 · DE/FR cross-check of every summary (`summary/crosscheck.py`), on by default (`SUMMARY_CROSSCHECK=0` turns it off): numbers (dates, percentages, amounts) are compared rule-based; an adversarial Apertus reviewer looks for contradictions and omissions in two passes with the texts in both orders, and only findings of both passes count; for each serious finding an Apertus referee decides from the judgement (decisive considerations and operative part) which language is right, the other one is rewritten once and both are checked again; what still disagrees is an error in the check report and is shown in the UI. A failing checker never blocks a summary. · DE and FR are written independently from the judgement, and the existing check only compared cited articles and considerations: the stored 8C_221/2025 run has DE claiming a remand and naming a CHF 250 cost award that FR does not mention. The judgement, not one language, is the reference. On by default at the team's request; the reviewer is not yet measured against the gateway (`eval/crosscheck_eval.py`: Suva's DE/FR pairs as they are and with a falsified FR text), so its false-alarm rate is unknown. 2 extra Apertus calls per summary, up to 5 with a rewrite. · Ben + Claude Code

- 2026-11-28 · Carrying a lawyer's edit over to the other language is no longer one rewrite of the whole text (`align_language`, "the edited version is authoritative 1:1") but `summary/align.py` (#102): the code finds the changed sentences itself, Apertus gets one small task per changed passage (JSON: does it change the substance, which sentences of the other language say it, quoted, and how they read now), and the code replaces only those sentences. The judgement (cited considerations, outcome) is in the prompt as the reference for the legal meaning; the lawyer's edit still wins, an edit against the judgement is carried over and noted. A last call compares both languages; its findings are shown as notes and change nothing. An answer that fails one of the checks in `align.planned_replacement` is not applied and the lawyer is told to carry that change over by hand (quote not in the text; a loosely quoted sentence whose changed words cannot be placed in the real sentence; replacement keeps less than 60 % of the old wording; more new sentences than the edit added; a figure that is neither in the old sentence nor in the edit; whole sentences removed although the edit removed no whole passage; no JSON). These checks limit what a wrong answer can do; they do not tell whether a new sentence is legally right. At most 8 changed passages are carried over per save, the rest is noted. While the other language is still the generated text, the edit is compared with the generated text of the edited language, so an edit that could not be carried over earlier is caught up. Known limits: the notes are written in the language of the aligned text, not of the interface; the closing check does not get the judgement; a new paragraph in the edit is added to an existing paragraph of the other language. · Requirement of the team: no translation, change only the passages concerned, use the judgement as reference, point out contradictions instead of inventing. Three simpler variants were tried against Apertus 70B on 8C_580/2025 with four edits (substance, wording only, against the judgement, addition): one free-text prompt for the whole text missed changes or dropped half a paragraph; asking for sentence numbers picked wrong sentences. The final variant, in its last run (after an independent review of the pull request and its fixes), carried over 2 of the 4 changes of substance correctly (one of them against the judgement, with a note saying so), left the wording-only edit alone and reported the other 2 as not carried over, without writing anything wrong. The gateway does not answer the same way every time: in the run before, Apertus treated the wording-only edit as a change of substance and rewrote one sentence, and added an amount from the judgement that the edit did not contain; the second is now refused by the code, the first can still happen, so the aligned text stays marked «angeglichen, bitte prüfen». The closing check listed real differences and at least one false one. One judgement and four edits are no evaluation. Trade-off: 1 call per changed passage plus 1 (about 15–40 s on the shared gateway), and changes Apertus cannot place stay manual. The notes are not stored.
