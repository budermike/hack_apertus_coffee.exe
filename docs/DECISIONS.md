## Decisions
- 2026-11-27 · Multilingual Embeddings (`embed.py`, issue #5) + Local Vector-DB & FTS5 (`crawl/vectordb.py`, issues #8, #9, #30, #37) use `intfloat/multilingual-e5-small` (MIT open-weights, 384-dim, DE/FR/IT, MPS/CPU; swappable via `EMBEDDING_MODEL`) stored in SQLite (`metadata.sqlite3` 6.4 MB + separate auto-rebuilt `fts.sqlite3` for FTS5 full-text search) + compressed NumPy archives (`vectors/*.npz` ~79 MB tracked in Git; `search_index.npz` auto-rebuilt locally in ~3 s) on Python 3.13. · Probing `https://gateway.keera.ch/api/v1/models` confirmed no `/v1/embeddings` endpoint is served (404). Chosen over TF-IDF (only 9.7 % Q1/2026 Recall@30, no cross-lingual DE/FR/IT semantics; `e5-small` + hybrid reaches 51.6 % Recall@30 and 90.3 % Recall@100) and over larger models like `BAAI/bge-m3` / `e5-large` (fast ~20 min laptop backfill vs. ~1.5–2 h, compact ~79 MB Git vectors & Docker image #31, 100 % air-gapped via `local_files_only=True`). Separating `fts.sqlite3` from `metadata.sqlite3` keeps every Git-tracked file well under GitHub's 100 MB limit while letting teammates pull all 6,053 pre-computed E5 vectors (incl. 23 Q3/2025 Suva references) immediately without re-embedding. · Abi + Antigravity
- 2026-11-27 · Crawler (`crawl/crawl.py`) has two sources: `bger` (official, final target) and `entscheidsuche` (open mirror, same 2096 judgements for Q2/2026). · bger.ch's bot protection (Incapsula) blocked us during development; the mirror lets us test end to end now. Switch with `"source"` in `configs/crawl.json` or `--source bger`. · Abi + Claude Code
- 2026-11-27 · Unit of crawling and caching is the day: `data/raw/_index.json` lists every completely saved day; one JSON per judgement in `data/raw/<YYYY-MM>/`. · bger.ch shows at most 90 hits per query, so a span must be split anyway; the index lets a second run make no requests (#7) and is what `ensure_period` (#35) needs. Caveat: judgements published later for an already covered day are only found with `--refresh`. · Abi + Claude Code
- 2026-11-27 · Summary in two steps (facts JSON, then DE and FR written separately from the facts, the cited consideration passages and 2 Suva examples of the same language). · FR must not be a translation (challenge); the facts step keeps DE and FR consistent. · Mike + Claude Code
- 2026-11-27 · Consistency check (#16) is rule-based, not a second model call: cited considerations and articles must exist in the judgement, the closing paragraph must match the operative part, DE and FR must cite the same. One regeneration with the errors as feedback, then flag in the UI. · Reproducible, cheap, catches the typical hallucinations (invented E. numbers, articles, wrong outcome). Outcome detection checked on all 6030 crawled judgements: not detected for 39 (0.6 %), for 8C/9C 2 of 1084. · Mike + Claude Code
- 2026-11-27 · Summary reuses triage's `GatewayConfig`, reference corpus and TF-IDF embedder (`hack_apertus_coffee_exe.triage`) instead of copying them. · One place for gateway config and the Suva reference data. · Mike + Claude Code
- 2026-11-27 · Summaries DB (#26) is SQLite via stdlib `sqlite3`: tables `cases` (date + source URL), `summaries` (one row per case, language, version), `case_numbers` (all case numbers of joined cases). Path from `SUMMARY_DB_PATH`, default `data/processed/summaries.db`; `*.db` is git-ignored. Schema in `docs/SCHEMA.md`, code in `summary/store.py`. · Central, searchable store without a new dependency; runs on-premise / air-gapped. · Mike + Claude Code
- 2026-11-27 · Summary rows are append-only: never `UPDATE`/`DELETE`. Edit and approval each add a new version; `approved` is a copy of the `edited` text. · Full history for Suva; the original model output stays traceable. · Mike + Claude Code
- 2026-11-27 · A summary is generated at most once per case and language; batch and on-demand both go through `get_or_generate`, no regeneration. · Done criterion of #26 (restart shows all summaries without LLM call); saves gateway calls; regenerated text can never hide a lawyer's edit. · Mike + Claude Code
- 2026-11-27 · Model output (`generated`) counts as released without review; only human edits need approval. An edit always stores `model = 'human'` and `prompt_version = NULL` (enforced by a `CHECK`). UI shows newest `approved`, else `generated`; an open edit is shown as draft. · Keeps the flow short for the demo. Trade-off: unreviewed model text is in the knowledge base, so the UI should mark `generated` as such. · Mike + Claude Code
- 2026-11-27 · `coherence_ok` is set once when the summary is generated (part of the summary pipeline: summary compared with the judgement) and never changed; `NULL` for human edits. · Keeps rows append-only; no check on human text. · Mike + Claude Code
- 2026-11-27 · Joined cases (e.g. `1D_1/2025, 1D_2/2025`) get one summary under the first number; `case_numbers` maps every number to it (filled from crawl `case_ids`). · Duplicates would let edits and approvals drift apart; lookup still works with any number. · Mike + Claude Code
- 2026-11-27 · Triage feedback (manual traffic light, table `feedback`) is deferred until the traffic-light system is defined. Agreed so far: re-scoring may overwrite `model_score`, never a manual override; same colour = no-op, other colour = mean score of the cases currently in that colour. · Ampel thresholds not decided yet. · Mike + Claude Code
- 2026-11-27 · Merged the summary pipeline (`summary_build`) onto the #26 store: its own `SummaryStore` was replaced by `store.py`; the pipeline's extra data is kept as columns `title`, `issues` (coherence findings), `facts`, `examples`. `--force` regeneration was removed. `cases.decision_date`/`url` are nullable so an incomplete crawl record does not stop a batch. · One store, one set of rules (append-only, generate once, edits are `human`). · Mike + Claude Code
- 2026-11-27 · UI backend for summaries is `summary/api.py` on stdlib `http.server` (no new dependency); it also serves the static UI. `PUT …/summary` stores changed texts as `edited` versions instead of overwriting (deviates from the comment in `api.js`); new `POST …/summary/approve`; `DELETE /knowledge-base` returns 405. `GET /judgements` (triage list) and feedback are not part of it. · Keeps the contract of `api.js` where it does not conflict with the append-only rule. · Mike + Claude Code
