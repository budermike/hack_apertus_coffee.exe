## 3. Findings on `main`

1. **A search for a period without stored results writes into tracked folders.** The background job crawls into `data/raw/` (tracked) and writes the Vector-DB, so the working tree is dirty after such a search. Read and run (without network: fails cleanly, nothing is written besides lock and journal files).
2. **In the container a new period cannot be ingested.** `sentence_transformers` is not installed in the image (run: `ModuleNotFoundError`), and ingestion loads the embedding model (read). The stored quarter works fully.
3. **The UI's default period (last three months) has no stored results**, so the first search of a new user starts a crawl instead of showing the shipped Q2 list. Enter 01.04.–30.06.2026.
4. `.env.example` had fallen back to `APERTUS_*` as main names for endpoint and model through a merge; restored to `LLM_*` together with this addendum.
5. The container runs as root, and `docker compose up` without `--build` reuses an older local image (the README says `--build`).

## 5. What these checks do not show

- Nothing was run against the real Apertus gateway in this addendum: quality of summaries, of the aligned other language and of the French reasons is not checked here.
- Fetching a new period with network access was not run.
- Learning from decisions is shown to be safe, not to be useful: with the list protected, recall did not change in any of 80 simulated runs, and the ranking did not get measurably better.
- The reference data of the challenge partner in `judgements/` is in a public repository; whether that is permitted is still for the team to confirm with Suva (audit report, section 11).
